Laboratory record. This history expressly distinguishes Beta deployment from sovereign integration. Public availability does not make a Beta a production release and does not anticipate a promotion decision.

1. Recording rule

Each significant public Beta retains an identity independent of Grammar and IR version numbers. The B1, B2, B3… series identifies experimental realizations and does not replace normative Language versioning.

A Beta may be deployed and technically functional without being integrated. Only evidenced promotion can relate a specific Beta to a sovereign production cut.

B2 constituted capabilities

  • Two browser-visible source units, each with independent SVP-ES/SVP-EN selection.
  • Assembly occurs after each unit has been analyzed; the interface does not concatenate sources or token streams to manufacture a third program.
  • Convergence into one IR 0.3 and global well-formedness checking after canonical representation is merged.
  • Editor and result are shown in parallel panels on wide screens, with internally scrollable output and stacked layout at reduced widths.
  • Primary actions appear before content in both the editor and the assembly workspace.
  • A six-example library with ES and EN variants. An unmodified library example switches to its matching variant when the source profile changes; custom or modified code is preserved without transformation.
  • A modified-source marker distinguishes an intact library example from edited content.
  • Bilingual documentary navigation for Security, Diagnostics, Features, Beta History and Programming and metrics, with explicit preservation of interface language when returning to the Playground.
  • Explicit source-profile selection and no language autodetection.

Boundaries B2 does not cross

  • B2 does not yet constitute a general project or module system or an arbitrary number of units.
  • It does not define an entry point, main program or import semantics.
  • It does not manufacture one fused .svp source from units written in different surfaces.
  • Its Security document is not a general certification and does not replace the security review required before promotion.
  • It does not promote SVP-ES or multi-source assembly into the sovereign repository.

5. Proposals and debt for later Betas

The following entries retain material future work without turning it into an automatic implementation commitment. Where B2 has realized only part of a proposal, the remaining scope is kept explicit.

  • LAB-P001 · Integrated development environment

    State: PROPOSAL

    B2 visually reserves a space for evolution toward projects, multiple files, tabs, symbols, diagnostics, IR and traces, but does not yet constitute those capabilities. A future environment must reuse the sovereign compiler and must not introduce an independent second parser.

  • LAB-P002 · Edit state and modified-file marker

    State: IN BETA

    B2 distinguishes intact library examples from modified content and exposes a modification marker. Integration into a complete project or development-environment model remains open.

  • LAB-P003 · Structured diagnostics and localizable presentation

    State: PROPOSAL

    The existence of bilingual Diagnostics pages does not yet constitute structured diagnostics. Code, position or span, structured arguments and presentation text still need to be separated without changing error identity or source profile.

  • LAB-P004 · Persistent source-profile provenance

    State: IN BETA

    B2 retains the active profile and source SHA-256 per unit in the assembly interface. Full persistent provenance including profile version, catalogue and grammar while preserving source_sha256 remains open.

  • LAB-P005 · Multi-source infrastructure, projects and modules

    State: IN BETA

    B2 realizes the experimental case of two units with independent profiles and global validation. A general project model, arbitrary unit count, versioned compatibility, dependencies, a possible entry point and possible export of assembly IR or manifest remain open. B2 does not manufacture a fused source.

  • LAB-P006 · Editing tools derived from the canonical catalogue

    State: PROPOSAL

    Syntax highlighting, completion and navigation should derive from the canonical catalogue or generated artifacts, avoiding side vocabularies that may diverge from the compiler.

  • LAB-P007 · Versioned evolution toward additional linguistic profiles

    State: UNDER STUDY

    The possibility of additional surfaces is retained without retroactively reserving words that would break earlier programs. B2 constitutes no third profile and establishes no committed implementation order.

  • LAB-P008 · Static-footprint strategy as profiles grow

    State: UNDER STUDY

    If table growth makes the WebAssembly footprint material, distribution or loading strategies must be compared without moving semantic decisions to remote translation, active databases or external services.

  • LAB-P009 · Visual Unicode security

    State: PROPOSAL

    Invisible or directional Unicode controls and presentation risks in code, strings and comments still require explicit governance before visual-security guarantees can be stated for the ES/EN experience.

  • LAB-P010 · Specific trajectory/Trajectory parity review

    State: CHECK PENDING

    This remains a specific check until sufficient reproducible evidence exists to close or discard it. The entry does not by itself declare a current defect.

  • LAB-P011 · Stable Language manual through GitHub Wiki

    State: PROPOSAL

    A stable user and programming manual is proposed, beginning with the Playground once the relevant capabilities have been promoted. The manual is not part of B2 experimental authority.

  • LAB-P012 · Security dossier per Beta and promotion

    State: IN BETA

    B2 has a dedicated Security page in Spanish and English for observable controls and limits. Before any promotion, a complete, versioned and traceable security review must be retained together with the exact identity of the Beta and evaluated artifacts.

6. Proposal-continuity rule

A proposal that survives several Betas retains its identifier and state. The operating states in this record are PROPOSAL, UNDER STUDY, READY FOR PROTOTYPE, IN BETA, DISCARDED and PROMOTED. A discarded proposal must retain its technical reason; a promoted proposal must link the integration evidence.

IN BETA only means that an experimental realization exists within the declared scope; it does not mean sovereign integration or promotion.
